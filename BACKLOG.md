# Оставшиеся дефекты и проверки

Актуально на 18 августа 2026 года. Здесь перечислены незакрытые проблемы, выявленные при разборе сценария подготовки и отправки отклика. Общий продуктовый план находится в [README.md](README.md#план-до-персонального-mvp).

## P0 — реальная отправка формы

- [ ] Провести безопасный прогон на живой форме Lever до финального нажатия Submit. Проверить распознавание подписей, обязательности, radio/checkbox, select, загрузки PDF и динамически появляющихся вопросов.
  - Готово, когда в интерфейсе нет технических ключей вместо понятных названий, а число блокирующих полей совпадает с формой в браузере.
- [ ] Установить точную причину, по которой конкретная форма Lever не отправлялась из Chrome for Testing: селектор кнопки, заблокированный переход, browser validation, CAPTCHA, редирект или неподтверждённый результат отправки.
  - Готово, когда интерфейс показывает конкретную причину остановки и следующее действие пользователя.
- [ ] Проверить реальную отправку только после явного разрешения пользователя и сохранить подтверждение результата: страницу успеха, reference или отметку о ручной отправке.
  - Автоматическая отправка без отдельного подтверждения запрещена.
- [ ] Определить окончательный сценарий браузера: управляемое тестовое окно с понятной ручной передачей управления либо подключение к обычному Chrome пользователя.
  - Готово, когда пользователь может вручную исправить форму, продолжить проверку и завершить отклик без потери состояния.
- [ ] Проверить разрешённые адреса и редиректы Lever. Добавлять только конкретные необходимые домены, не расширяя allowlist на произвольные сайты.

## P1 — устойчивость заполнения

- [ ] Покрыть настоящую многостраничную форму. Текущий сквозной тест проверяет динамическое раскрытие полей и повторное сканирование на одной странице.
- [ ] Проверить восстановление незавершённого отклика после перезапуска приложения и закрытия браузерного окна.
- [ ] Добавить обезличенные регрессионные образцы реальной разметки Lever, Greenhouse и одной нестандартной ATS.
- [ ] Проверить специальные элементы: поисковый combobox, autocomplete адреса, условно обязательные поля, согласия, группы checkbox и дополнительные вложения.
- [ ] Улучшить запасное определение названия поля, чтобы `Неизвестное поле` и внутренние идентификаторы появлялись только в технической подсказке.
- [ ] Добавить переход из списка ошибок непосредственно к соответствующему полю в управляемом браузере, если это позволяет форма.
- [ ] Провести ручной smoke-test на Greenhouse и одной нестандартной ATS после завершения проверки Lever.

## P1 — пробелы и вопросы

- [x] Для каждого пробела добавить явные решения: «добавить подтверждаемый факт», «не могу подтвердить», «не относится ко мне» и «принять риск».
- [x] Сохранять решения по пробелам, чтобы отклонённый или неприменимый вопрос не возвращался после каждого повторного анализа без объяснения.
- [ ] Проверить группировку на нескольких реальных вакансиях: одна тема не должна порождать десятки почти одинаковых требований и вопросов.
  - Добавлен обезличенный регрессионный срез Kotlin/Java Internal Tools Developer: повторяющиеся строки сворачиваются в тематические группы с доступом к исходным формулировкам. Для закрытия пункта нужны ещё реальные вакансии других профилей.
- [x] Показывать, как новый факт изменил оценку: какое требование стало подтверждённым, а какое осталось без доказательств.

## P2 — диагностика и приватность

- [ ] Добавить выгрузку обезличенного диагностического пакета для разбора проблем формы: адрес без query/fragment, типы полей, понятные подписи, статусы и коды ошибок — без введённых значений.
- [ ] Расширить проверки на утечки персональных данных в ошибках Playwright, исключениях, URL, снимках состояния и журнале повторного запуска.
- [ ] В диагностике различать ошибку сайта, ограничение управляемого браузера, ошибку распознавания поля и отсутствие подтверждённого ответа.

- Выбор последней вакансии заполняет форму новой вакансии.

- Технические статусы и причины остановки переведены в пользовательские формулировки.

- Добавлен локальный Lever-подобный сквозной тест заполнения, повторного сканирования и подтверждённой отправки.
